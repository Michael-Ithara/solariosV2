# AI Insights

## Overview

AI insights are generated by a Supabase edge function that runs an XGBoost model (exported to ONNX format) for energy consumption forecasting, plus a rule-based nudge template system for personalized recommendations.

---

## Key Files

| File | Purpose |
|------|---------|
| `supabase/functions/ai-energy-insights/index.ts` | Edge function — ML inference + nudge generation |
| `supabase/functions/ai-energy-insights/xgboost_energy_model.onnx` | Trained ONNX model |
| `src/hooks/useAIInsights.tsx` | Frontend hook — fetches recommendations and forecasts |
| `src/components/ai/` | AI insight UI components |

## Edge Function: `ai-energy-insights`

**Runtime:** Deno (Supabase Edge Functions)

**Trigger:** Called from the frontend via `supabase.functions.invoke('ai-energy-insights', { body: context })`

### ONNX Model Pipeline

1. Model is lazy-loaded on first invocation from `./xgboost_energy_model.onnx`
2. Input features are extracted from user context:

```ts
features = [
  avgDailyConsumption,   // kWh
  avgDailySolar,         // kWh
  netUsage,              // consumption - solar
  peakHour / 23,         // normalized peak usage hour
  occupants,             // household size
  homeSize / 3000,       // normalized floor area
  solarCapacity,         // kW installed
  batteryCapacity,       // kWh
  electricityRate,       // local rate
  growthRate,            // historical trend
  month / 11,            // seasonality
  isWeekend ? 1 : 0,     // day type
]
```

3. ONNX inference runs via `onnxruntime-web` with the WASM execution provider
4. Output is a forecasted monthly consumption value (kWh)

### Fallback Behavior
If the ONNX model fails to load or inference errors, the function falls back to a heuristic forecast (average-based) and still generates nudges from templates.

## Nudge Template System

Each nudge is built from a 4-part template structure:

```ts
interface NudgeTemplate {
  scenario: string;                        // Situation description
  actionVerb: string;                      // What the user should do
  specificItem: (ctx) => string;           // The specific device/action
  contextWhen: (ctx) => string;            // When to do it
  benefitWhy: (ctx) => string;             // Why (savings/CO2)
  category: string;                        // e.g. 'solar', 'hvac', 'scheduling'
}
```

Templates are evaluated against the user's context and the most relevant nudges are selected. Context includes current solar production, consumption patterns, peak usage hours, and device inventory.

## Frontend Hook: `useAIInsights`

Location: `src/hooks/useAIInsights.tsx`

```ts
const { recommendations, forecasts, loading, error, refetch } = useAIInsights();
```

- Fetches from `ai_recommendations` and `ai_forecasts` tables
- Optionally calls the edge function to regenerate fresh insights
- Used in `src/pages/Insights.tsx` and `src/pages/Dashboard.tsx`

---

## Database Tables

| Table | Purpose |
|-------|---------|
| `ai_recommendations` | Stored nudge recommendations per user |
| `ai_forecasts` | Stored monthly forecasts per user (consumption/generation) |

Both tables have RLS — users only see their own rows.

### `ai_recommendations` columns
- `title` — short display title
- `description` — full nudge text (generated from template)
- `priority` — `high` / `medium` / `low`
- `expected_savings_kwh` — projected kWh reduction
- `expected_savings_currency` — projected cost saving

### `ai_forecasts` columns
- `target` — `consumption` or `generation`
- `value` — forecasted kWh
- `period_start` / `period_end` — forecast window
- `model` — identifier of the model used

## Insight Feedback

Users can give thumbs up/down on nudges. This is tracked via `src/hooks/useInsightFeedback.tsx`. Feedback data can be used to improve future nudge selection (currently stored but not yet used for retraining).
